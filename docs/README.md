# OctoAcme Project Management Docs

This folder describes OctoAcme's customer-first, iterative, and data-informed approach to project delivery. Work moves through initiation, planning, execution and tracking, release and deployment, then retrospective; risks and communication are managed throughout.

The Project Manager coordinates schedules, delivery, risks, and communication; the Product Manager defines outcomes and prioritizes work. Developers build and test increments, QA validates acceptance criteria, and stakeholders provide input and approvals. Teams use standups to surface progress and blockers, weekly delivery and PM/Product Manager syncs to align on risks and dependencies, and regular stakeholder updates to keep decisions visible.

Quality is built into each stage: backlog items have acceptance criteria and a Definition of Done; pull requests should be small, link to issues, and receive review. CI runs tests, linting, and security scans; teams add unit and applicable integration tests, smoke-test critical flows, and perform manual QA when needed. Releases require passing checks, a rollback or mitigation plan, and post-deployment verification; retrospectives turn outcomes into tracked improvements.
